# security/ — IA-driven security tooling

Python files, dependency-free (stdlib `urllib` only), KISS:
* `common.py` — shared IA backend transport (Ollama / Claude API / Claude CLI). Backend selection, multi-host Ollama routing + per-model `@url` pins, DYNAMIC `num_ctx` (fit_ctx sizes to the payload + the reply cap `_ollama_num_predict()` + margin, low floor → a small view runs a small/fast KV cache; grows per-call as the agentic convo grows; `CC_OLLAMA_MIN_CTX`), `think` control, `chat()`/`chat_with()`. The reply cap is 2048 ONLY when `ollama_think` is explicitly false — with `think` unset a reasoning model spends the cap on thought and every reply gets chopped at the same byte, which the agent loop reads as a stuck model.
* `server.py` — agentic SECURITY auditor of the TCP-reachable server (whole-file scan + exploit). `codecheck` mode = per-function security review (`agentic.py`) + exploit. Adversarial validation is ON BY DEFAULT (reuses the primary `--model`): a 2nd pass re-attacks every finding the primary model couldn't confirm on its OWN separate budget (`SECSERVER_ADVERSARIAL_BUDGET`; analysis time not charged to the primary), also hunting game-LOGIC exploits (object dup / illicit-get / impossible action) proven via GDB state inspection; a CONFIRMED there wins. `SECSERVER_ADVERSARIAL_MODEL=<spec>` validates with a DIFFERENT (usually stronger) model; `=off` disables it.
* `codecheck.py` → **MOVED to `tools/codecheck/`** (general code-quality, NOT security). Its per-function engine (build_index / build_views / verdict cache / tidy / types) is REUSED by `server.py codecheck` + `agentic.py` (imported across the boundary via sys.path); see `tools/codecheck/CLAUDE.md`.
* `agentic.py` — multi-IA agentic WORKGROUP engine shared by codecheck (tools/) + server.
* `codetree.py` / `pycodetree.py` — C/C++ (clang LLVM-IR) / Python (ast) call graph: function index + caller/callee trees.
* `secret.py` — leak SCANNER. Standalone per file (NO related-file loading). Deterministic regex (internal paths, public IPs) + LLM (tokens/passwords/API-URLs). Scans git-tracked+untracked (`all`, default), `staged`, `changed`, or explicit files. Exit 2 = leaks found.

## IA backend — default model `gemma4:26b`
`OLLAMA_HOST` (a scheme-less `host:port` is accepted; BRACKET IPv6) selects the access mode by URL alone — the code path is identical:
* **local** (default): `http://127.0.0.1:11434`.
* **remote direct**: a remote Ollama daemon on `:11434`.
* **remote via PHP router** (recommended for shared use): an Ollama-API-compatible PHP endpoint that routes to the optimized instance.
* **Claude (API)**: `CC_IA_BACKEND=claude` + a credential (`ANTHROPIC_API_KEY` console key, or out-of-repo `claude_api_key`). Console-key / pay-per-token path.
* **Claude (CLI)**: `CC_IA_BACKEND=claude-cli` — shells out to the official `claude -p` (must be logged in once). HARD RULE: a Pro/Max SUBSCRIPTION may ONLY be used via this CLI backend; replaying its OAuth token through the API backend violates Anthropic's Consumer Terms (tokens were BLOCKED Jan 2026). No token/key is held — `claude` authenticates itself. All built-in tools disabled; runs from a temp cwd; `claude_cli_preflight()` pings once up front.

**HARD RULE — never commit a remote/router URL or its IP / SSH coords.** They embed infrastructure IP. The real backend config lives OUT of the repo: `~/.config/CatchChallenger/ia-settings.json` (override `CC_IA_SETTINGS`) — `{"ollama_host": "http://[...]:11434"}` (single) or `ollama_backends` (multi-host table); the router's deploy SSH coords go in its `_router_ssh` note there. `OLLAMA_HOST` env overrides the file. In-repo `ia-settings.example.json` is an IP-free template only. Default model overridable via `CC_IA_MODEL`, `--model=` (server), `CC_SECRET_MODEL` (secret).

## `server.py codecheck` — per-function SECURITY review (shared engine)
`server.py codecheck` reuses the function-by-function engine in `tools/codecheck/codecheck.py` (via `agentic.py`) but with the SECURITY prompt + the clang static-analyzer check-set, then `run_exploit()` develops a proof (no proof => no claim). The LLM is MANDATORY (`CC_IA_PANEL`, never auto; each spec `<model>[@ollama-url]` or `claude` = the official CLI); `>= 2` => panel/workgroup. Bound a run: `CC_CODECHECK_SCOPE` / `CC_CODECHECK_LIMIT`. SCOPE default = `general` + `server` ONLY (server-reachable code; client/ + tools/ are OUT — the exploit phase boots the SERVER, so nothing there can ever be proven), minus vendor + build/generated trees. Candidates are attacked in remote-reachability order (login pre-auth → wire parser → handlers). A model-declared CONFIRMED needs a real probe (RUN or GDB), never code-reading alone; lint-only (bugprone/cert) blocks are exploit CONTEXT, only `clang-analyzer-*` opens a session on its own. The general (non-security) auditor, the limited-view design, the four force-multipliers (algorithmic clang-tidy / triviality skip / compute-only incremental cache / adversarial verify) and the context-safety (dynamic num_ctx, agentic budget guard, text-loop collapse) all live in **`tools/codecheck/`** — see its CLAUDE.md. (`test/codecheck.py` is the all.sh stage over that engine: it self-tests the per-turn invariants AND runs a QUALITY review — bugs/illogic/perf, never security — with `--model=` (default `gemma4:26b`); see `test/CLAUDE.md`.)

## Exploit verdicts — UNPROVEN is NOT "safe"
The exploit is the FORMAL PROOF, not the bug report: `CONFIRMED` = proof (crash/hang/valgrind error/GDB state), `NOT-EXPLOITABLE` = the model REFUTED it (named the guard on the path), `UNPROVEN` = neither — budget exhausted, model looped/truncated/stalled, or CONFIRMED claimed without evidence. UNPROVEN findings stay on the to-fix list (`unproven.md` per dir + aggregate, "To fix" section of `REPORT.md`); never report them as clean. Not queued for a proof at all (reported UNPROVEN directly): static-analysis-only findings from checks that can never be remote (`STATIC_NOISE_CHECKS`; `CC_EXPLOIT_DROP_NOISE=0` overrides) and files the exploit target binary does not compile (read from `BUILD_DIR` objects + depfiles; `CC_EXPLOIT_ANY_FILE=1` overrides).

Detection and proof are separate skills: `SECSERVER_EXPLOIT_MODEL` / `--exploit-model=` puts a coder model on the exploit loop while `--model` keeps auditing.

**Start an IA session only when it can change the verdict.** Each session is a full budget (~1 h), so: the valgrind retry runs only for a MEMORY-safety finding (`MEMORY_CLASS_RE` — Memcheck says nothing about a hang/dup/auth/ctor-order defect); the adversarial pass runs over an UNPROVEN finding only with a DIFFERENT validator model (the same model just spent a full budget there — measured 12/12 same-model passes reproduced the primary verdict), while over a REFUTATION it always runs, since a second opinion can catch a wrong "this is safe".

## secret.py config + report — also OUT of the repo
Path allow-list / detection patterns: `~/.config/CatchChallenger/secret-scan.json` (`CC_SECRET_CONFIG`); a starter template is written on first run. Findings print to **stdout only** — nothing is written to disk unless `CC_SECRET_REPORT=<path>` opts into a file (keep it out of the repo; it may quote redacted secrets). The config is out-of-repo so the scanner never writes a leak back into the tree it scans.
